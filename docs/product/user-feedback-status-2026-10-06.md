띄어쓰기 나열 자르기는 일부러 좁게 잡았다. 다음 경우에는 자르지 않는다.

- 문장 전체가 음식 하나의 이름이면 자르지 않는다(참치 김밥 → 참치김밥).

- 첫 단어가 음식이 아니면 자르지 않는다(편의점 김밥 라면).
- 음식 사이에 양이 아닌 말이 있으면 자르지 않는다(우유 넣은 커피, 라면 끓여서 계란 넣고).

저장 스키마는 바꾸지 않았다. 새 필드 `amountAssumed`와 `listed`는 서버→브라우저 응답에만 있고 기록에는 남지 않는다.

## 4. 결정이 필요한 것

1. **제품 지원 범위:** 맨 "햇반"을 햇반 흰밥 행(210g, 315 kcal)으로 기록할지 정해야 한다. 현재 별칭 정책("별칭은 같은 음식이어야 한다")으로 보면 햇반 흰밥과 같은 음식이다. 다만 잡곡·현미 변형과 갈라지는 지점을 어떻게 둘지도 같이 정해야 한다.
2. ~~포장량 고정 방식~~ → 2026-10-06 사용자 결정: **칸 방식**. 사람은 어느 칸이 "한 개"인지만 정하고, 숫자는 행에서 가져온다. 대표 제품 10개로 시작하고 사용자가 말로 고칠 수 있게 한다. 맨 "포카칩"은 오리지널 66g으로 기록하고, 맛은 답장에서 안내한다. §5에 반영했다.
3. **소금빵:** 품목대표가 없다. 체인 행 하나를 대표값으로 쓸지, 계속 칼로리를 묻게 둘지 정해야 한다.
4. **이야기 속 나열의 "둘 다" 선택지:** `라면 끓여서 계란 두 개 넣고`처럼 자르지 않는 경우에 "어떤 음식인가요?"에 "둘 다"를 넣을지 정해야 한다.
5. ~~커밋 단위~~ → 2026-10-06 사용자 결정: 네 단위로 커밋, push 승인. 1번 햇반 바로 기록, 3번 소금빵은 체인 행 하나를 대표값으로, 4번 "둘 다" 선택지 추가 — 셋 다 반영함. **2번(제품별 포장량 고정 방식)만 미결**이고, 사용자가 추가 설명을 요청했다.
