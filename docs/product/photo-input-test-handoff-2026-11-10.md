# Claude Code 인계 — 사진 입력 테스트 준비

작성: 2026-11-10 (KST), Codex. 기준 브랜치 `main`, HEAD `2f49196`. 이 문서는 테스트 실행 결과가 아니다. 시작 시 [STATE](../STATE.md)·[DECISIONS](../DECISIONS.md)와 현재 Git 상태를 다시 확인한다.

## 현재 요청과 시작 조건

- 이번 요청은 **Claude Code 작업 세션이 테스트할 수 있도록 세팅만** 하는 것이다. Codex는 사진 수집·생성·실제 모델 호출·서버 실행을 하지 않았다.
- 웹에서 사진을 가져오거나 생성 이미지로 실제 식사 사진을 대신하지 않는다. 사용자가 제공한 사진이 없으면 준비 상태로 멈춘다.
- 실제 Anthropic·Jev 호출은 후속 사용자 지시에서 실행 범위와 건수·비용 상한이 정해진 뒤 한다. 키 등록·사진 배치·과거 1건 실행을 새 묶음의 승인으로 해석하지 않는다.
- 운영 환경변수·개인정보처리방침 시행일·배포·커밋·push는 이번 준비 범위에 없다. 기존 Phase 3 미커밋 변경과 `.claude/launch.json`을 보존한다. 같은 checkout에서 다른 세션이 쓰는 중이면 겹쳐 수정하거나 빌드하지 않는다.

## 확인된 연결과 남은 검증

- 사진 입력 코드는 로컬 커밋 `bf8baa6`에 있다. [기존 보고](../STATE.md)에 따르면 로컬 3213에서 그림 1건으로 실제 호출이 성공했다. 이는 이번 세션의 재검증이나 실제 식사 사진의 품질 근거가 아니다.
- `.env.local` 파일 존재만 이번에 확인했다. 내용·키 값·현재 키 유효성은 확인하지 않았다. 사용자 환경 파일은 바꾸지 않는다.
- 실제 사진 품질, 입력창의 나열 문장을 실제 Jev가 기록으로 받는지, 토큰·비용, 휴대폰 카메라·Safari·HEIC는 미검증이다.
- [recognizer](../../src/ai/photo/recognizer.ts)는 현재 `usage`와 응답의 실제 `model`을 반환하지 않는다. `/api/photo`만 관찰해서는 비용 실측을 할 수 없다. 과거의 장당 1~2센트는 추정이며 측정값으로 복사하지 않는다.

## 준비된 입력·결과 자리

- [photo-samples](../../photo-samples/README.md): 사용자 제공 사진 자리. 현재 이미지 0장이다.
- [manifest.example.csv](../../photo-samples/manifest.example.csv): 빈 사진 목록 양식. 실제 `photo-samples/manifest.csv`는 로컬 전용이다.
- [results.example.csv](../../photo-samples/results.example.csv): 빈 결과표. 실제 결과는 `eval-results/photo-input-<실행일시>/results.csv`에 복사한다. 이 경로 전체는 이미 Git 제외 대상이다.
- 한식 한 상·단품·포장제품·음료·어두운/비스듬한 사진·음식 아닌 사진을 포함한 10~20장은 **후속 시험 구성 제안**이며 현재 확보한 자료가 아니다. 부족한 유형은 미검증으로 남긴다.
- 기대 음식명·양의 허용 범위는 호출 전에 사람이 확인한다. 출력된 음식명을 사후에 정답으로 삼지 않는다. 사진별 원문 출력, 사람이 수정한 문장, 문자 경로의 결과를 구분해 적는다.

## 후속 세션의 로컬 실행

이 절은 **사진과 실행 승인이 준비된 뒤** 수행할 명령이다. Codex는 실행하지 않았다.

1. 테스트 전용 브라우저 프로필과 전용 PowerShell을 사용한다. 로그인하지 않으며 기존 사용자 기록을 시험 데이터로 쓰지 않는다. 3000 포트와 기존 서버·빌드 작업을 건드리지 않는다.
2. `.env.local`의 `ANTHROPIC_API_KEY`·`PHOTO_INPUT`과 문자 경로의 `TYPESAFE_API_KEY` 설정 여부를 값 출력 없이 확인한다. Jev 키가 없으면 mock 결과를 실제 판단 검증으로 보고하지 않는다. `.env.local`은 출력·수정하지 않는다.
3. 아래 값은 전용 프로세스에만 적용한다. 로컬 요청이 운영 공유 카운터·계정에 닿지 않도록 한다. 사진 모델·한도는 [env](../../src/env.ts)의 잠정값을 확인하되 임의로 높이지 않는다.

```powershell
# 실행 승인 후, 저장소 루트의 전용 터미널에서만 실행
$env:ACCOUNT_ENABLED = 'off'
$env:ACCOUNT_RECOVERY_ENABLED = 'off'
$env:RATE_LIMIT_STORE = 'memory'
$env:APP_ORIGIN = 'http://localhost:3213'
$env:LEGACY_HOSTS = ''
$env:PHOTO_INPUT = 'on'
pnpm build
if ($LASTEXITCODE -ne 0) { throw '사진 QA 빌드 실패: 서버를 시작하지 않음' }
pnpm start --port 3213
```

`http://localhost:3213`에서 시험한다. build와 start에 같은 설정을 적용해야 홈의 사진 버튼과 서버 스위치가 일치한다. 기존 `verify-photo-live` launch 항목은 **start만** 하므로 최신 빌드 확인 없이 바로 쓰지 않는다. `verify-photo`는 가짜 키를 넣는 실패 경로용이다. 포트 충돌 시 다른 세션의 프로세스를 종료하지 말고 별도 포트를 정해 origin도 맞춘다. 전용 터미널을 닫으면 위 임시 설정도 끝난다.

현재 기본 제한은 분 3회·하루 20회·서비스 하루 200회다. 같은 서버에서 순차 실행하고 429이면 `Retry-After`를 따른다. 재시작·식별자 변경으로 일간 제한을 우회하지 않는다. 앱 요청 1건에 SDK 재시도가 붙을 수 있어 앱 요청 수를 유료 호출 수나 비용 상한과 동일시하지 않는다.

## 사진별 확인 순서

1. 최초 카메라 버튼에서 전송처 안내를 확인한다. 취소 시 업로드가 없어야 한다. 동의 후 파일을 선택한다. 최초 안내 재시험은 별도 테스트 프로필에서 한다.
2. 브라우저 Network에서 `/api/photo`가 `image/jpeg`로 전송되는지 확인한다. 긴 변은 **최대** 1280px(작은 원본은 확대하지 않음), 크기는 1,500,000바이트 이하여야 한다. 위치정보 제거는 실제 전송본을 확인한 경우에만 검증 완료로 쓴다. HAR·요청 본문·base64를 공통 문서에 붙이지 않는다.
3. 실제 응답의 kind·문장·지연을 결과표에 적고 음식명과 양을 별도로 평가한다. kcal·영양소 표현이 입력창에 들어오지 않아야 한다. 음식 아님·판독 불가는 안내로 끝나야 한다. 필터 경계의 악의적 출력은 기존 mock 단위 테스트로 구분한다.
4. **기록 버튼을 누르기 전** 입력창만 채워지고 식사 기록 수·오늘 합계가 그대로인지 확인한다. `photo_only_record_delta`는 0이어야 한다. 기존 입력이 있으면 뒤에 붙는 동작도 확인한다.
5. 승인된 Jev 호출 범위 안에서 대표 사진의 문장을 **그대로** `기록`한다. `먹었어`를 미리 덧붙이지 않는다. 자연스러운 나열이 기록되는지, 음식별 양·데이터셋 근거·추정 안내를 확인한다. 실패하면 원문과 원인을 남긴다. 사람이 고쳐서 성공한 결과는 `edited_sentence`로 따로 구분한다.
6. 테스트 전용 프로필의 기록으로 정정·삭제까지 확인한다. 실제 사용자 데이터는 지우지 않는다. 사진 인식 오류·미지원 데이터·문자 판단 오류를 결과 `notes`에 구분한다. 모바일 폭 확인과 실제 휴대폰/Safari 시험도 구분한다.

## 비용·마무리 기록

- 비용 측정까지 후속 범위에 포함되면 호출 전에 테스트 전용 관찰 방법을 준비한다. SDK 응답의 실제 model·usage 토큰(캐시 포함)만 수집하고 키·이미지·요청 본문은 기록하지 않는다. 현재 API에는 이 관찰 기능이 없다. 계측 구현은 이번 준비에 포함하지 않았다.
- 단가는 실행 시 공급자 공식 자료로 확인하고 기준일·출처와 계산식을 결과에 적는다. fallback 설정이 있어 요청 모델과 실제 모델을 구분한다. usage를 확보하지 못하면 비용은 미측정으로 둔다. HTTP 지연만으로 토큰·비용을 추정해 실측으로 보고하지 않는다.
- 결과에는 총 사진 수, 성공/실패·음식명/양 판정, 수정 필요 여부, 기록 전 자동 저장 여부, 실제 Jev 확인 건수, 측정된 비용과 누락 범위를 적는다. 키·원본 사진·개인 대화는 공통 문서에 남기지 않는다.
- 코드 변경이 생기면 그 영향에 맞춰 typecheck·lint·단위 테스트·build를 수행한다. 기존 사진 단위 테스트는 `pnpm exec vitest run src/app/api/photo/photoRoute.test.ts`이며 recognizer를 mock한다. 실제 품질 검증과 혼동하지 않는다.
- 종료 시 본인이 실행한 서버만 종료하고 [STATE](../STATE.md)에 직접 검증·미검증·다음 행동을 구분한다. 운영 활성화나 모델·한도 확정으로 자동 진행하지 않는다.
