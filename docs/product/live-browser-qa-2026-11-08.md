# 운영 페이지 브라우저 QA — 2026-11-08

작업 세션 전달용. **관찰한 동작과 수정 제안을 구분한다.** 이 문서는 결함 수정·회귀 테스트·배포가 완료됐다는 뜻이 아니다.

## 검증 범위와 기준

- 대상: `https://how-much-calories-left.vercel.app/`의 실제 공개 화면. 2026-11-08 KST에 Codex 인앱 브라우저에서 직접 입력, 버튼 클릭, 새로고침, 식사·대화 기록 화면 이동으로 확인했다. 이번 QA에서 배포 ID·서버 로그·로그인 상태는 확인하지 않았다.
- 기준: 시작 당시 오늘 식사 0건, 목표 2,540 kcal. 브라우저에는 과거 기록이 이미 있었으므로 신규 사용자 경험이나 계정 동기화 검증으로 확대하지 않는다. 기대 동작은 [D01·D02·D03·D07](../DECISIONS.md)과 화면이 직접 안내한 흐름을 기준으로 적었다.
- 결과: 재현 가능한 결함 후보 5건, 기대대로 동작한 주요 흐름 13건. 일부 문장 판단은 AI 응답에 의존하므로 수정 후 동일 입력을 운영 환경에서 재확인해야 한다.
- 정리: QA 중 만든 오늘의 식사 기록은 전부 UI에서 제거했다. 새로고침 뒤 **0 / 2,540 kcal**를 확인했다. 테스트 대화는 대화 기록에 남아 있다. 코드·설정·배포는 변경하지 않았다.

## 결함 후보 — 작업 우선순위 순

### QA-01 · 명시한 `반 봉지`가 1그릇으로 기록됨 — 높음

1. 오늘 화면에 `라면 반 봉지 먹었어`를 입력한다.
2. 기대: 먹은 양이 `반`임을 반영한다. 봉지와 데이터셋의 그릇 기준을 환산할 수 없다면 필요한 정보를 묻고, 전체 1그릇을 확정 기록하지 않는다.
3. 실제: `라면 1그릇 ~451 kcal`가 추가됐다. 답장은 `라면 반 봉지의 무게를 몰라 1그릇으로 잡았어요. 양이 다르면 "라면 150g으로 고쳐줘"처럼 말해주세요.`였다.
4. 비교: 이어서 `라면 반 그릇 먹었어`는 `라면 반 그릇 226 kcal`로 기록됐다. `반` 표현 전체가 실패하는 현상은 아니다.
5. 영향: 사용자가 명시한 분량보다 큰 값이 오늘 합계와 잔량에 반영된다. 음식·단위별 변환과 추정 안내를 함께 점검할 필요가 있다.

### QA-02 · 화면이 안내한 `먹었어`를 그대로 입력해도 음식 기록으로 이어지지 않음 — 중간

1. 오늘 화면에서 `오늘 저녁 떡볶이 먹을까?`를 입력한다.
2. 실제 첫 답장: `떡볶이 1인분은 약 259 kcal예요. 오늘은 2,218 kcal 남았어요. 드셨으면 "먹었어"라고 말해 주세요.` 식사 기록은 생기지 않았다.
3. 안내대로 `먹었어`를 입력하고, 나온 `기록할까요?`에서 `네`를 누른다.
4. 기대: 앞서 말한 떡볶이를 이어받아 기록하거나, 음식명 재입력이 필요하다는 점을 첫 안내에서 명확히 알린다.
5. 실제: `무엇을 드셨는지 알려주세요.`로 끝났고 떡볶이는 기록되지 않았다. 화면의 후속 입력 안내와 실제 대화 상태가 맞지 않는다.

### QA-03 · 먹지 않았다는 문장을 기존 기록 삭제 요청으로 해석 — 중간

1. 오늘 라면 기록 2건이 있는 상태에서 `오늘 아침 라면 먹으려다가 안 먹었어`를 입력한다.
2. 기대: 먹지 않은 음식으로 판단해 기록을 추가·수정·삭제하지 않고 그 문장에 맞게 답한다.
3. 실제: `라면을 두 번 기록했어요. 어느 기록인가요?`라며 기존 라면 2건을 삭제 후보로 제시했다. `해당 없음`을 선택하자 `아무것도 지우지 않았어요. 지울 음식 이름을 다시 말씀해주세요.`라고 답했다.
4. 영향: 이번에는 확인 단계가 있어 실제 삭제는 없었다. 다만 비섭취 문장이 삭제 의도로 분류되고, 사용자가 후보를 잘못 고르면 기록이 지워질 수 있다.

### QA-04 · 복합 섭취 문장에서 알려진 라면을 미등록 음식으로 처리 — 중간

1. `라면 한 봉지 끓였는데 반만 먹었어`를 입력한다.
2. 기대: 라면을 식별하고 실제 먹은 반을 반영하거나, 봉지 기준 환산에 필요한 양을 구체적으로 묻는다.
3. 실제: `말씀하신 음식은 아직 정보가 없어요. 대략 몇 kcal였는지 알려주시면 그대로 적을게요.`라는 응답이 나왔다. 새 기록은 생기지 않았다. `그만두기`로 해당 흐름을 취소했다.
4. 비교: 더 짧은 `라면 반 그릇 먹었어`에서는 라면을 식별했다. 복합 문장의 음식·섭취량 분리가 실패한 사례로 재확인이 필요하다.

### QA-05 · 미래 식사 계획에 일반 기록 안내만 응답 — 낮음

1. `내일 떡볶이 먹을 거야`를 입력한다.
2. 기대: 오늘 식사로 기록하지 않고, 먹을 계획에 맞는 짧은 응답을 한다([D07](../DECISIONS.md)).
3. 실제: 오늘 합계는 유지됐지만 답장은 `먹은 걸 말씀해주시면 기록할게요.`였다. 계획이라는 맥락을 받지 못했다.

## 기대대로 동작한 흐름

| 입력·조작 | 브라우저에서 확인한 결과 |
| --- | --- |
| `배고파` | 식사 0건 유지, 배고픔에 맞는 짧은 답장과 현재 잔량 표시 |
| `김밥 먹었어` | `김밥 1줄 ~322 kcal` 기록, 기본량 추정 안내와 상세의 제공량 기준 표시 |
| `방금 김밥 한 줄이 아니라 반 줄이었어` | 기존 322 → 161 kcal로 정정, 중복 추가 없음 |
| `김밥 반 줄 더 먹었어` | 161 kcal 기록을 별도 추가, 두 건 합계 322 kcal |
| 김밥 한 건 삭제 → `되돌리기` | 합계 161 kcal로 감소 후 322 kcal로 복구. 새로고침·식사/대화 기록 화면에서도 일치 |
| `오늘 저녁 떡볶이 먹을까?` | kcal와 당시 잔량을 답하고 식사는 기록하지 않음. 단, 후속 입력 안내는 QA-02 참조 |
| `사과는 안 먹고 바나나 한 개 먹었어` | 사과는 제외, 바나나 `~77 kcal`만 기록 |
| `사과 1개랑 바나나 1개 먹었어` | 두 음식 125 + 77 kcal 추가. 앞선 바나나 포함 합계 279 kcal |
| 바나나가 두 건일 때 `바나나 1개를 2개로 고쳐줘` | 대상 선택 후 고른 기록만 77 → 154 kcal 수정 |
| `바나나 지워줘` → `해당 없음` | 삭제 대상 선택을 요구했고 아무 기록도 지우지 않음 |
| `말차 초코바 200kcal 먹었어` | 음식명과 사용자가 제시한 200 kcal로 기록. `처음 보는 간식 200kcal 먹었어`처럼 음식명이 모호한 경우는 `직접 입력` 200 kcal로 표시 |
| `별빛젤리 1봉 먹었어` → `150kcal` | 모르는 음식의 kcal를 물은 뒤 후속 숫자를 `별빛젤리 1봉 150 kcal`에 연결 |
| `오늘 남은 칼로리 얼마야?` | 당시 섭취 1,583 kcal·잔량 957 kcal를 답하고 기록은 유지 |

## 작업 세션에 넘길 확인 사항

- 먼저 QA-01의 **실제 섭취량과 저장량 불일치**를 재현하고, 봉지·그릇처럼 기준 단위가 다를 때의 정책을 확정한다. 수정 후 `반 봉지`와 `반 그릇`을 각각 확인한다.
- QA-02는 안내 문구와 후속 대화 상태를 한 흐름으로 검증한다. `먹었어`와 `네`를 눌렀을 때 무엇이 기록되는지까지 확인한다.
- QA-03·04는 문장 전체의 섭취 여부와 음식·분량 식별을 함께 검증한다. 질문이 나온 것만으로 통과 처리하지 말고, 잘못된 수정·삭제 후보가 나타나는지도 본다.
- QA-05는 [D07](../DECISIONS.md)의 먹을 계획 응답 기준과 맞춰 확인한다.
- 이번 QA는 로그인·계정 동기화, 모바일 화면, 다른 브라우저, 날짜 경계, 서버 저장 상태를 검증하지 않았다. 통과 표는 해당 범위의 품질 보증으로 해석하지 않는다.
